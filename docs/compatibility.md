# PhysFX 1.x 兼容性政策

本文是 PhysFX `v1.0.0` 起的公开兼容承诺。承诺覆盖编辑脚本 JSON、`.physfxproj`、
`.pfxtpl` 和公共 C++/插件 SDK；安全修复可以拒绝畸形、越界或不可信输入，这不属于兼容性
回归。

## 文件格式

三种格式使用独立的整数格式版本。0.3-0.6 已产生的受支持样本都映射为格式版本 1；
`.pfxtpl` 历史 manifest 未写 `formatVersion` 时按 1 读取。

| 格式 | 当前版本 | 读取策略 | 1.x 写入策略 |
| --- | ---: | --- | --- |
| 编辑脚本 JSON | 1 | 读取 `version=1`；忽略未知可选字段；未知命令给出可定位错误，不静默执行 | 始终写 1；只新增可选字段或新命令，不改变已有字段含义 |
| `.physfxproj` | 1 | 读取 `version=1`；`curves` 等后加字段缺失时使用保守默认值；未知可选字段忽略 | 始终写 1；保留旧节点/命令语义，新增信息使用可选字段 |
| `.pfxtpl` | 1 | `formatVersion` 缺失视为 1；未知可选 manifest 字段忽略；签名失败只影响信任标识，不阉割开源功能 | 新包显式写 `formatVersion: 1`；签名覆盖规范化 manifest 和内容 |

读取方遇到大于自身支持版本的格式时必须拒绝并显示：检测到的版本、当前支持版本和升级建议；
不得猜测后继续写回。写入方不主动升级格式版本，也不把未知字段剥离后覆盖原文件；打开未来版本
只允许只读诊断。`v1.5` 必须能打开由 `v1.0` 写出的有效文件。

历史兼容样本来自 `v0.4.0`、`v0.5.0`、`v0.6.0` 标签，固定到 `tests/compat/fixtures/`，
其来源标签、原始路径和 SHA-256 记录在同目录清单。样本进入 CTest 后在整个 1.x 生命周期常驻，
不得用重生成覆盖历史内容。

## 公共 C++ API 与插件 SDK

公共 API 是各模块 `include/physfx/` 下经 `docs/api-audit.md` 登记的头文件。应用目录、
`src/`、测试辅助和 spike 代码不是公共 API。`physfx::v1` 提供稳定命名入口；现有
`physfx::<module>` 拼写在 1.x 保留为兼容入口。需要动态库可见性的类和自由函数使用
`PHYSFX_API`，静态构建中该宏为空。

版本遵循 SemVer：

- patch：缺陷、安全、性能和文档修复，不改变有效调用的源码/二进制行为合同；
- minor：只追加 API、可选字段、带默认实现的能力或新命令；
- major：删除/改名、改变参数/返回类型、虚函数布局、字段含义或默认行为等破坏性变更。

公共结构体布局和 C++ ABI 跨编译器本来不稳定。PhysFX 1.x 的二进制兼容承诺限定为同一
受支持工具链、运行库和构建选项；跨工具链插件必须从源码重编译。发布包应记录编译器、标准库、
架构和 `PHYSFX_VERSION`，加载器发现不匹配时拒绝加载并给出重编译建议。

## 弃用流程

1. 新 minor 版本先提供替代 API，并在头文件使用 `[[deprecated("替代项；最早移除版本")]]`。
2. 弃用项至少保留一个完整 minor 版本，且在整个 1.x 中不做破坏性删除；确需删除只能进入下一 major。
3. CHANGELOG、迁移指南和编译诊断必须同时给出替代写法。
4. 安全问题优先通过输入拒绝、服务端关闭或兼容包装修复；只有无法安全兼容时才发布明确公告并由维护者裁决。

## 维护分支

正式版发布时建立 `release/1.x`。修复先进入 `master` 并通过全量门禁，再由带原 PR/issue
链接和 DCO 的 cherry-pick 回移；功能、研究 spike 和格式升级不回移。P0/P1 修复优先，
P2 由维护者按风险批准，P3 留在后续 minor。支持周期和安全披露入口见 `SECURITY.md`。
