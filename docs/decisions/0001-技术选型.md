# ADR 0001：技术选型与 Phase 1 构建策略

## 背景

PhysFX 需要同时承载高性能物理模拟、AI 场景理解和跨平台视频处理，因此需要稳定的 C++ 核心、Python 胶水层、
可复现的依赖管理和可替换的后端边界。

## 决策

- 核心语言采用 C++20，构建系统采用 CMake 3.26+ Presets。
- 依赖声明采用 vcpkg manifest，仅声明轻量的 GoogleTest 与 pybind11；FFmpeg、OpenCV、Taichi 等重型库留待后续阶段。
- 物理、视频 IO、渲染和 AI 均通过抽象接口隔离，Phase 1 使用桩实现。
- Python 包提供可编辑安装的 `version()` 门面，并保留可选的 pybind11 `_physfx` 扩展构建目标；未安装
  pybind11 时使用纯 Python 回退，以保持默认构建零依赖。
- Windows 预设使用 `MinGW Makefiles`，Linux/macOS 使用 `Unix Makefiles`，以覆盖常见本地工具链。

## 影响

本阶段无需下载 FFmpeg、OpenCV、Taichi 或图形 SDK 即可构建和运行测试；真实能力接入时需要补充 vcpkg 依赖和相应适配器。
未启用 vcpkg 工具链时，CMake 使用无第三方依赖的 CTest 桩测试；找到 GoogleTest 后会额外构建并发现 GoogleTest 冒烟测试。
